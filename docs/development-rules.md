# WildWalk AI 开发规则（优先级最高）

本规则用于保证《WildWalk AI》在低成本、高可维护前提下稳定迭代。

## A. 总体规则

1. 先文档后代码：每个功能先写 1 页以内设计说明（目的、输入、输出、验收）。
2. 先确定性后 AI：所有核心数值只由后端规则计算，AI 只负责解释与叙事。
3. 先小步后扩展：每次只交付一个“可运行、可测试、可回滚”的小功能。
4. 先可回放后复杂：所有随机事件必须受 `seed` 控制，支持问题复现。
5. 先低风险后硬核：先做低难度路线，稳定后再上高海拔/极端天气。

## B. 编码规则

1. 每个模块必须有错误处理与日志（输入校验、异常分类、告警点）。
2. 每个模块至少配 1 个最小测试（单元或集成）。
3. API 参数必须明确类型、默认值、边界值。
4. 禁止在代码中硬编码密钥，统一使用 `.env` 占位符。
5. 同步更新 `README.md`，保证文档和代码一致。

## C. Git 规则（必须执行）

1. 分支约定：
   - `main`：稳定可发布
   - `dev`：日常开发集成
   - `feature/*`：功能分支
   - `hotfix/*`：紧急修复
2. 提交频率：
   - 完成一个最小可运行点，立即提交一次。
   - 若有风险改动，先提交“保护快照”再继续。
3. 提交信息模板：
   - `feat: ...` 新功能
   - `fix: ...` 修复问题
   - `docs: ...` 文档更新
   - `test: ...` 测试补充

## D. 测试与验收规则

1. 输出测试结果必须包含 ✅ / ❌。
2. 测试失败必须写：失败原因 + 修复建议 + 下次验证步骤。
3. 每个功能都要附带“非技术同学可操作”的手动验收步骤（3~5 步）。

## E. 平台规则

- 目标平台：移动端跨平台（iOS + Android）。
- 若出现兼容性冲突：
  1) 推荐先保证单平台稳定（建议 iOS-first 或 Android-first）
  2) 再评估双平台兼容成本与工期
