# WildWalk AI 多 Agent 协同开发方案

本方案用于把复杂任务拆成并行小任务，提高迭代速度并降低返工。

## 1. Agent 角色与职责

### 1) 数值策划 Agent（Game Balance）

- 负责生存数值模型：体力、水分/饥饿、失温、心理压力
- 产出：参数表、公式、边界条件、死亡/失败阈值
- 验收：固定种子下结果可复现，极端输入不崩溃

### 2) AI 叙事策划 Agent（AI Narrative）

- 负责 AI 播报模板、叙事风格、事件文案、幻觉状态文案
- 产出：Prompt 模板、叙事片段库、敏感词与安全策略
- 验收：不篡改数值，只解释规则结果，文案风格统一

### 3) 路线与数据 Agent（Scenario Data）

- 负责路线剧本库（Waypoint、天气、海拔、地形）
- 产出：标准化场景 JSON、难度分级、数据校验脚本
- 验收：每条路线至少可跑通 10 回合无结构错误

### 4) 后端规则引擎 Agent（Backend Core）

- 负责回合计算、事件调度、可见性分发（公开/私有）
- 产出：回合计算 API、状态机、日志与回放能力
- 验收：单测覆盖核心公式，集成测试覆盖完整回合

### 5) 客户端 UI Agent（Mobile UI）

- 负责行动面板、聊天界面、回合结果展示
- 产出：移动端交互页面、状态可视化组件、错误提示
- 验收：非技术用户可在 3 分钟内完成一局体验

### 6) QA 与自动化 Agent（QA）

- 负责测试计划、自动化测试与回归清单
- 产出：冒烟测试、回放测试、回归报告
- 验收：关键路径（进房-行动-结算-下一回合）稳定

## 2. 协作节奏（每个迭代 2~3 天）

1. 产品 Owner 定义目标：本轮只做一个可验证能力
2. 各 Agent 并行开发：每日同步一次风险与阻塞
3. 集成与回归：由 Backend + QA 联合验收
4. 文档收敛：更新 `README.md` 与本目录文档
5. Git 快照：每完成里程碑提交并打标签

## 3. 任务看板模板

- `TODO`：待拆解需求
- `DOING`：当前进行中（最多 3 条）
- `REVIEW`：待联调/待验收
- `DONE`：已完成并有测试结果

## 4. 最低可行并行包（首轮推荐）

1. 数值策划 Agent：完成 `v0` 参数与公式
2. 后端规则 Agent：完成单回合计算 API
3. UI Agent：完成行动提交 + 结果展示
4. QA Agent：完成 5 条冒烟用例

> 原则：先把“能跑一回合”做通，再增加社交背刺、长线路线、复杂事件。
